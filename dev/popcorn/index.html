Popcorn

Popcorn is a compact linear notation for OpenMath objects, introduced by Peter Horn and Dan Roozemond in OpenMath in SCIEnce: SCSCP and POPCORN (Calculemus/MKM 2009, LNAI 5625). It writes 1 + $x where the XML encoding needs a document of six elements:

julia> using OpenMath

julia> obj = OMS"arith1#plus"(OMInteger(1), OMVariable("x"));

julia> OpenMath.popcorn(obj)
"1 + \$x"

julia> OpenMath.xml(obj)
"<OMOBJ xmlns=\"http://www.openmath.org/OpenMath\" version=\"2.0\"><OMA><OMS cd=\"arith1\" name=\"plus\"/><OMI>1</OMI><OMV name=\"x\"/></OMA></OMOBJ>"

Popcorn is for reading. It is not part of the OpenMath standard and not an interchange format: it has no syntax for cdbase, and an OMFOREIGN loses its encoding. Exchange objects in one of the four encodings.

write_popcorn writes to a stream, OpenMath.popcorn returns a String, and read_popcorn reads it back:

julia> read_popcorn("lambda[\$x -> \$x^2 + 1]")
OMOBJ(OMBIND(OMS(fns1#lambda), [x], OMA(OMS(arith1#plus), OMA(OMS(arith1#power), OMV(x), OMI(2)), OMI(1))))

julia> read_popcorn(OpenMath.popcorn(obj)).object == obj
true

What write_popcorn writes reads back as the same object, but for what Popcorn has no syntax for. That is a tested property, on generated objects.

A name that is not a plain identifier — or that is one of the grammar's keywords, such as or — is written in single quotes: $'x-1', logic1.'and'.

Infix operators

The symbols of the common Content Dictionaries have infix forms, and brackets appear only where the grammar needs them:

julia> x, y = OMVariable("x"), OMVariable("y");

julia> OpenMath.popcorn(OMS"arith1#times"(OMS"arith1#plus"(x, OMInteger(1)), y))
"(\$x + 1)*\$y"

julia> OpenMath.popcorn(OMS"logic1#implies"(OMS"relation1#lt"(x, y), OMS"relation1#eq"(x, y)))
"\$x < \$y ==> \$x = \$y"

list1#list and set1#set are written [a, b] and {a, b}. A symbol with no infix form, or an operator applied to a number of operands its form cannot show, is written as a call: arith1.plus($x), logic1.'and'($x, $y, $z).

A few symbols are written without their Content Dictionary: sin, cos, tan, exp, sinh, cosh, tanh, pi, e, i, infinity, true, false, not, min, max, abs, sum, product, root, lambda, forall, exists.

julia> OpenMath.popcorn(OMBinding(OMS"quant1#forall", [OMBoundVariable("x")], OMS"relation1#geq"(OMS"transc1#exp"(x), OMInteger(0))))
"forall[\$x -> exp(\$x) >= 0]"

Reading

read_popcorn reads the reference grammar, and a little more than this package writes: hexadecimal integers (0x1F), /* comments */, <> for !=, and the if … then … else … endif and while … do … endwhile forms of prog1. A chain a + b + c is one arith1#plus of three operands, while (a + b) + c keeps its brackets. Errors are OpenMathParseErrors with the byte offset of the token at fault:

julia> read_popcorn("\$x < \$y < \$z")
ERROR: OpenMathParseError: "<" does not chain; put one side in brackets at byte 9

It does not read x::T, which the reference library accepts only once a type symbol has been configured, nor any bare name outside the list above.

How this follows the reference grammar, and where it departs from the reference library, is in the design note.
