Module

OpenMath.OpenMath — Module
OpenMath

A Julia implementation of the OpenMath 2.0 standard: an object model for the semantics of mathematical objects, and readers and writers for the official encodings.

Phase 1 provides the object model, validation and the normalisation passes. The four endorsed encodings — XML, JSON, Strict Content MathML and binary — are all implemented; see ROADMAP.md for what remains.

Examples

julia> using OpenMath

julia> e = OMS"arith1#plus"(OMInteger(1), OMVariable("x"))
OMA(OMS(arith1#plus), OMI(1), OMV(x))

julia> isvalid_openmath(e)
true

julia> canonicalize(e).applicant.cdbase
"http://www.openmath.org/cd"

OpenMath.OMForeign — Type
OMForeign(encoding, value; id = nothing)

Non-OpenMath content carried inside an OpenMath object (standard §2.1.1). The optional encoding describes how value should be interpreted.

value is the verbatim source of the foreign content, not decoded text. The standard allows arbitrary XML there — presentation MathML is the common case — so decoding entity references would make embedded markup indistinguishable from text that merely looks like markup, and the round trip would stop being lossless (REQ-OM-003). A writer therefore emits value unchanged, and refuses an object whose foreign content is not a well-formed XML fragment rather than producing a document that cannot be read back.

Examples

julia> using OpenMath

julia> OMForeign("text/plain", "not OpenMath")
OMFOREIGN(text/plain, "not OpenMath")
source
OpenMath.OMReference — Type
OMReference(href; id = nothing)

A reference to another OpenMath object (standard §3.1.2).

Two kinds, and the difference matters. An internal reference has a fragment-only href such as "#s1" and points at an element carrying that id in the same document; expand_references resolves it, and a missing target is an error. An external reference carries any other URI and points into a different document — the binary encoding gives the two separate tokens, 30 and 31, precisely because they are not the same thing. An external reference cannot be resolved without fetching, so the passes leave it alone rather than treating it as broken.

See isinternal.

Examples

julia> using OpenMath

julia> OMReference("#a")
OMR(#a)
source

Normalisation passes

OpenMath.resolve_cdbase — Function
resolve_cdbase(x; base = CD_BASE) -> typeof(x)

Push the inherited cdbase onto every symbol, and clear it from the composites that merely carried it. cdbase scopes lexically in every encoding, so resolving it is what makes two objects comparable regardless of where the attribute was written (REQ-CAN-003).

Examples

julia> using OpenMath

julia> a = OMApplication(OMSymbol("mycd", "f"), [OMSymbol("mycd", "g")];
                         cdbase = "http://example.org/cd");

julia> resolve_cdbase(a).applicant.cdbase
"http://example.org/cd"
source
OpenMath.minimize_cdbase — Function
minimize_cdbase(x; base = CD_BASE) -> typeof(x)

The inverse of resolve_cdbase: hoist each cdbase to the outermost object at which it applies, and drop it wherever it repeats what is inherited. This is what a writer wants, since the standard expects cdbase to be emitted only where it changes (REQ-CAN-004).

Examples

julia> using OpenMath

julia> a = OMApplication(OMSymbol("arith1", "plus"), [OMInteger(1)]);

julia> minimize_cdbase(resolve_cdbase(a)) == a
true
source
OpenMath.collapse_attributions — Function
collapse_attributions(x) -> typeof(x)

Flatten OMATTR(OMATTR(o, a), b) into OMATTR(o, [a…, b…]), throughout x. Innermost attributes come first, preserving the order in which they apply (REQ-CAN-005).

Only an attribution that carries no cdbase of its own is merged, since merging one that does would change what its attributes mean. canonicalize therefore resolves cdbase before collapsing, so that the normal form does not depend on where the base was written.

Examples

julia> using OpenMath

julia> k1 = OMAttributePair(OMS"ecc#a", OMInteger(1));

julia> k2 = OMAttributePair(OMS"ecc#b", OMInteger(2));

julia> collapse_attributions(OMAttribution([k2], OMAttribution([k1], OMVariable("x")))).attributes == [k1, k2]
true
source
OpenMath.expand_references — Function
expand_references(x) -> typeof(x)

Replace every OMReference by a structural copy of the element carrying the matching id (standard §3.1.2).

Raises OpenMathReferenceError on a cycle — "an OpenMath element may not dominate itself" — or on a dangling reference, and OpenMathLimitError if expansion would exceed max_nodes (REQ-CAN-008).

Examples

julia> using OpenMath

julia> shared = OMApplication(OMS"arith1#plus", [OMInteger(1)]; id = "s");

julia> e = expand_references(OMApplication(OMS"arith1#times",
                                           [shared, OMReference("#s")]));

julia> e.arguments[2] == shared
true
source
OpenMath.share_structure — Function
share_structure(x; min_nodes = 2) -> typeof(x)

The inverse of expand_references: find repeated subtrees, keep the first occurrence, and replace the rest by OMReferences to it (standard §3.1.2).

expand_references(share_structure(x)) equals expand_references(x) — sharing changes how an object is written, never what it means.

The first occurrence is what becomes the definition, so no reference ever precedes its target. That is not a nicety: the binary encoding forbids forward references outright (§3.2.5), and a pass that produced one would build objects this package could not write.

min_nodes is the smallest subtree worth sharing. The default of 2 excludes leaves, for which a reference costs more than the leaf in every encoding the standard defines.

Examples

julia> using OpenMath

julia> sub = OMS"arith1#plus"(OMVariable("x"), OMInteger(1));

julia> shared = share_structure(OMS"arith1#times"(sub, sub));

julia> count(n -> n isa OMReference, collect_nodes(shared))
1

julia> expand_references(shared) == OMS"arith1#times"(sub, sub)
true
source

OpenMath.parse — Function
OpenMath.parse(src; format = :auto, mode = :strict) -> OMObject

Decode an OpenMath document.

format is :auto, :xml, :mathml, :json or :binary. :auto determines the encoding from the leading bytes. mode is :strict, :lenient or :recover; see read_xml.

strict applies only to MathML. The default refuses anything outside Strict Content MathML; strict = false applies the transformation of MathML 4 Appendix F, which is defined normatively — so it is a rule rather than a guess. See read_mathml.

Examples

julia> using OpenMath

julia> o = OpenMath.parse("""
           <OMOBJ xmlns="http://www.openmath.org/OpenMath">

           </OMOBJ>""");

OMA(OMS(arith1#plus), OMI(1), OMV(x))

OpenMath.xml — Function
OpenMath.xml(obj; pretty = false) -> String

Encode obj in the OpenMath XML encoding (standard §3.1).

pretty inserts indentation between elements. It never alters character data, so an OMSTR survives it unchanged (REQ-XML-010).

The writer is faithful to the object it is given: it emits cdbase wherever a node's base differs from the one it inherits, and nowhere else (REQ-XML-006). It does not rewrite the tree, so for the smallest output apply minimize_cdbase first — that hoists a base shared by a whole subtree onto the enclosing element.

Examples

julia> using OpenMath

julia> OpenMath.xml(OMObject(OMS"arith1#plus"(OMInteger(1), OMVariable("x"))))
"<OMOBJ xmlns=\"http://www.openmath.org/OpenMath\" version=\"2.0\"><OMA><OMS cd=\"arith1\" name=\"plus\"/><OMI>1</OMI><OMV name=\"x\"/></OMA></OMOBJ>"

OpenMath.read_binary — Function
read_binary(src; mode = :strict) -> OMObject

Decode the binary encoding (standard §3.2) from a byte vector, a string of bytes or an IO.

Given an IO, exactly one object is consumed and the stream is left positioned after its end tag, so a stream carrying several objects can be read one at a time. Given a byte vector, the whole vector must be one document.

:lenient is accepted for uniformity and does nothing: a misread byte desynchronises everything after it, so this encoding has no lenient dialect to accept. :recover returns a document carrying a moreerrors#encodingError rather than raising — the whole document, since there is nothing to resynchronise on part-way through.

Examples

julia> using OpenMath

julia> read_binary(hex2bytes("580200011019")).object
OMI(16)

Phrasebooks

OpenMath.Phrasebook — Type
Phrasebook()

The translation between OpenMath objects and Julia values, as a value.

A fresh phrasebook contains the built-in vocabulary — the same correspondence from_openmath uses. Add to it with define!, apply it with interpret and express, and make it the default for a dynamic scope with with_phrasebook.

Entries are keyed on (cdbase, cd, name), because the same cd and name under a different base is a different symbol (standard §2.1.4).

Examples

julia> using OpenMath

julia> p = Phrasebook();

julia> interpret(p, OMS"arith1#plus"(OMInteger(1), OMInteger(2)))
3

julia> define!(p, OMS"arith1#plus", (xs...) -> "intercepted");

julia> interpret(p, OMS"arith1#plus"(OMInteger(1), OMInteger(2)))
"intercepted"

define_variable!(p, f)

OpenMath.define_leaf! — Function
define_leaf!(p, f)

Teach p to turn a literal — an integer, float, string or byte array — into a value with f. The default is identity.

The reason this exists is narrower than it looks. A phrasebook whose symbols map onto ordinary Julia functions will evaluate an application of them to literals: transc1#sin applied to OMI(-8) reaches Base.sin with an Int and returns a Float64. For plain Julia that is exactly right. For a computer algebra system it is not — it should stay symbolic — and this is where that is said.

Examples

julia> using OpenMath

julia> p = Phrasebook();

julia> interpret(p, OMInteger(2))
2

julia> define_leaf!(p, v -> v isa Number ? float(v) : v);

julia> interpret(p, OMInteger(2))
2.0

OpenMath.sts_arity — Function
sts_arity(signature) -> Union{Nothing,Int}

The number of arguments a signature admits, or nothing when it is n-ary.

An STS signature reads mapsto(T₁, …, Tₙ, Result): the last argument is the result type, so the arity is one less than the number of arguments. A parameter wrapped in sts#nary or sts#nassoc makes the symbol n-ary — the sts dictionary defines both as "an arbitrary number of copies of the argument" — and then there is no fixed arity to report.
